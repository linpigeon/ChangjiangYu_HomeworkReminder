# 学习通状态探测（任务点 / 作业 / 考试）

> 探测时间：2026-10-12 · 真实账号实测（珠海科技学院，13 门课）
>
> 本文记录**已验证可用**的端点与字段语义。实现状态见文末。

---

## 一、结论速览

| 目标 | 能否获取 | 做法 |
|---|---|---|
| **每门课的未完成任务点数** | ✅ 可以 | `stucoursemiddle` 页面里的「待完成任务点」章节树 |
| **作业完成/未完成** | ✅ 可以 | `work/stu-work` 的 `aria-label` 自带状态（已在用） |
| **考试完成/未完成** | ✅ 可以 | `exam-ans/exam/phone/examcode` 的 `aria-label` 自带状态（已在用） |

**新版移动端接口普遍需要 `enc` 参数**（服务端加密令牌），纯 cookie 直调会返回
`enc校验失败`。本文所有端点都是**不需要 enc、cookie 直连即可**的那些——
这也是为什么走 HTML 页面而不是 JSON API。

## 二、课程列表（拿 ID 三元组）

```
GET https://mooc1-api.chaoxing.com/mycourse/backclazzdata?view=json&rss=1
```

返回 `channelList[]`，每项含：

| 字段 | 含义 | 用途 |
|---|---|---|
| `content.id` | **clazzId**（班级 id） | 下面所有接口都要 |
| `content.name` | 班级名（如 `2026-2027-1-通信`、`2026秋`） | 显示 |
| `content.cpi` | **personId** | 下面所有接口都要 |
| `content.course.data[0].id` | **courseId** | 下面所有接口都要 |
| `content.course.data[0].name` | 课程名（如 `信号与系统`） | 显示 |
| `content.isretire` / `isstart` | 是否已结课 / 是否已开始 | 可用来跳过结课课程 |

> ⚠️ **注意**：`content.id` 是 clazzId，`course.data[0].id` 才是 courseId。
> 两者混用会拿到别的课或空白页。

## 三、未完成任务点数（任务点）

```
GET https://mooc1-2.chaoxing.com/visit/stucoursemiddle?courseid={courseId}&clazzid={clazzId}&vc=1&cpi={personId}
Referer: https://mooc1-2.chaoxing.com/
```

- **不需要 `enc`**（已实测）
- 返回约 130–260 KB 的服务端渲染 HTML，标题形如 `<title>信号与系统-首页</title>`
- 页面里有 <b>「待完成任务点」</b> 区块，内含整棵章节树

### 结构

```html
<div class="units">                          <!-- 章 -->
  <h2 class="levelfirst clearfix">
    <span class="chapterNumber">第2章</span> ...
  </h2>
  <div class="leveltwo">                     <!-- 节 -->
    <h3><a aria-label="2.1 LTI系统的响应">
      <span class="chapterNumber">2.1</span>
      <span class="articlename" title="LTI系统的响应">...</span>
    </a></h3>
    <!-- 该层未完成任务点数 -->
    <input type="hidden" value="1" class="knowledgeJobCount"/>
    <em class="orange">1</em>

    <div class="levelthree" id="872412010">  <!-- 更深一层（可能没有） -->
      ... 同样的 articlename + knowledgeJobCount ...
    </div>
  </div>
</div>
```

### 语义与坑

- `knowledgeJobCount` 的 `value` 与并列的 `<em class="orange">` **值相同**
  （前者供 JS 汇总，后者是显示的小黄球），二者一致，可互为校验。
- **父层级的计数是子层级的汇总，直接求和会重复计数。**
  例：`4.8 LTI系统的频域分析 = 1` 实际是它下面其他子节点的汇总，
  而 `4.8.1 频率响应 = 2` 是独立的一项。朴素求和得 16，实际 **13**。
- **正确口径：只统计「内部不再嵌套更深章节」的叶子节点。**
  判定方法：对每个带任务点的节点，检查其位置之后、同一章单元内是否还存在
  更深层级（`levelthree`）的任务点标记；有则它是父层汇总，跳过。
- **两种结构都要支持**：有的课没有三级嵌套（`levelthree` 数为 0，
  如「人工智能与法律」，40 个任务点全在 `leveltwo`），有的课有
  （如「毒品危害与防范」）。按「是否有更深层子节点」判定，天然兼容两者。
- **没有「待完成任务点」区块 = 该课没有未完成任务点**（已结课/纯资料课）。
  13 门课里有 10 门属于这种情况。

### 实测结果（13 门课）

| 未完成任务点 | 班级 / 课程 | 说明 |
|---|---|---|
| **13** | 2026-2027-1-通信 / 信号与系统 | 10 个叶子章节 |
| **40** | 2026秋 / 人工智能与法律 | 40 个叶子章节（无三级嵌套） |
| **16** | 2026秋 / 毒品危害与防范 | 16 个叶子章节（有三级嵌套） |
| 0 | 其余 10 门 | 无「待完成任务点」区块（多数已开启结课模式） |

明细示例（信号与系统）：
`2.1.1 微分方程的经典解 1`、`4.2 傅里叶级数 1`、`4.5 傅里叶变换的性质 3`、
`4.7 周期信号的傅里叶变换 1`、`4.8 LTI系统的频域分析 1`、`5.1 拉普拉斯变换 2`、
`5.3 拉普拉斯逆变换 1`、`6.1 Z变换 1`、`6.3 逆Z变换 1`、`6.4 Z域分析 1`

## 四、作业状态

```
GET https://mooc1-api.chaoxing.com/work/stu-work
```

每条是一个 `<li data="…mtaskmsgspecial…">`，块内 aria-label：

```
作业名称{标题}作业状态{状态}所属课程{课程}(剩余时间{…})?
```

**实测出现的状态值**：

| 页面状态 | 语义 | 映射到 `TodoStatus` |
|---|---|---|
| `未提交` / `未交` | 未完成 | `NotStarted` |
| `待批阅` | 已提交、等老师批改 → **已完成学生侧动作** | `InProgress` |
| `已批阅` / `已完成` / `已结束` | 已完成 | `Completed` |

实测样本（5 条）：
```
[未提交] 信号与系统 — 第二章作业
[待批阅] 信号与系统 — 第一章作业
[待批阅] 电路分析 — 第五次作业 / 第四次作业 / 第三次作业
```

> `待批阅` 是当前实现 `ChaoxingSyncService.MapStatus` 里映射为 `InProgress` 的那类；
> 若希望它在界面上也算「已完成」，改这一处映射即可。

## 五、考试状态

```
GET https://mooc1-api.chaoxing.com/exam-ans/exam/phone/examcode
```

每条 `<li data="/exam-ans/exam/phone/task-exam?…">`，aria-label：

```
考试名称：{标题}; 考试状态：{状态};(剩余时间：{…})?
```

**实测出现的状态值**：

| 页面状态 | 语义 |
|---|---|
| `未交` | 未完成 |
| `已完成` | 已完成 |

实测样本（9 条）：
```
[未交]   人工智能与法律、毒品危害与防范
[已完成] 李白导读、信息技术与创新创业、期中考试、大学生心理健康教育、
         军事理论、大学计算机-计算思维导论、走近核科学技术
```

> 考试条目的「考试名称」往往就是课程名（页面没有单独的课程字段），
> 当前实现也据此把 `CourseName` 与 `Title` 设为同一个值。

## 六、实现状态

**已实现**：

- 作业 / 考试两个列表页的抓取与状态映射
  （`ChaoxingApiClient.GetHomeworkAsync` / `GetExamsAsync`，`ChaoxingSyncService.MapStatus`）
- **课程未完成任务点数**（`ChaoxingApiClient.GetPendingTaskPointsAsync` +
  `ChaoxingSyncService.SyncCoursesAsync`），以「课程」导航视图做**课程维度汇总**
- 课程列表改用 `backclazzdata?view=json`，一次拿到 clazzId / courseId / personId /
  课程名 / 班级名 / 是否结课

### 接入时踩到的两个坑（都已修，并有回归用例）

1. **不按「已结课」预过滤课程**。曾按 `isretire == 1` 跳过任务点查询以省请求，
   结果漏掉了 `信号与系统`（**13 个未完成任务点**）——它在响应里根本没有
   `isretire` 字段。真正已结课的课是 `isretire=1`，而缺失字段的既不是 1、
   也不该被当成已结课跳过。现在一律请求：没有「待完成任务点」区块的课程自然得 0。
2. **解析必须先按文档位置排序再判叶子**。`marks` 是按层级
   （`levelfirst`→`leveltwo`→`levelthree`）依次收集的，不是文档顺序；
   而「是否有更深层子节点」靠位置先后判定。不排序会漏掉
   「`leveltwo` 在前、它的 `levelthree` 在后」这种最常见情形，
   导致父层汇总值被当成叶子一起算进去（数字偏大）。

### 实测（`--cxcheck` 在线自检，真实账号）

```
  40  人工智能与法律（2026秋）
  16  毒品危害与防范（2026秋）
  13  信号与系统（2026-2027-1-通信）[已结课]
   0  其余 10 门
  课程数 13；有未完成任务点的 3 门；任务点合计 69
```

与独立 Python 探测的结果**逐项一致**（13 门课 / 40 / 16 / 13 / 合计 69），
互为交叉验证。

### 展示形态

课程维度汇总（不是逐条待办）：侧边栏新增「课程」导航，
每行一门课显示「课程名 + N 个任务点未完成」，点开右侧详情看未完成的小节明细。
角标为「有未完成任务点的课程数」（不是任务点总数——那是每门课的明细）。
选中课程时列表顶部不再显示「还没有雨课堂账号」引导（那一路只关学习通，会误导）。

理由：任务点粒度到小节，一门课动辄几十个（`人工智能与法律` 40 个），
拆成逐条待办会把列表淹掉。

### 自检

```powershell
.\HomeworkReminder.Desktop.exe --cxcheck     # 用本机已保存的学习通会话跑真实课程+任务点
```

只读，不修改远端状态。退出码 0 = 正常；3 = 无有效学习通会话。
