## 一、为什么是「正方教务」

国内高校教务系统以**正方**（`jwglxt`）占比最高，它的课表页有两种形态，且都有稳定的结构锚点：

| 形态 | 结构 | 可靠性 |
|---|---|---|
| **JSON 直取** | `xskbcx_cxXsKb.html` 返回体含 `kbList[]` | 最高（字段位置明确） |
| 列表视图 | `kblist_table` 的 `tbody#xq_N`，课块自带「周数/教师/上课地点」标签 | 高 |
| 网格表格 | 普通 `<table>`，表头含星期、首列节次 | 兜底（需要启发式分块） |

解析按上表顺序依次尝试，命中即用。**只产出节次**，具体几点上课由节次时间表推导——
这样周视图、待办、提醒三处的时间口径天然一致，不会各算一套。

## 二、数据模型

```
ScheduleItem      一条「星期 + 节次 + 连续周次段」的上课安排
PeriodSlot        单个节次的时间映射（第 N 节 08:00-08:45）
ClassSession      由 ScheduleItem 按周次展开出的某一天的具体课次
```

### 关键取舍：一门课可能对应多条

教务系统的原始记录常带**不连续周次**（如 `1-8,10-16周`）或**单双周**。
这里按「连续段」**拆开**，每条只表示一段连续周次：

- `1-8,10-16周` → 2 条（1-8、10-16）
- `1-15周(单)` → 1 条，`WeekParity = Odd`

好处是「某周是否有课」退化成一次简单区间判断，周视图与提醒都不必再做区间合并。
代价是同门课会出现多行——这是**符合事实**的（不同周次段本来就是不同的上课安排）。

### 停用节次的哨兵

某节的开始与结束时间**都是 `00:00`** 即表示该节停用：不参与先后/相邻重叠校验、
周视图不显示该节行、落在其上的课块也不显示。这样学校作息调整（例如某天只有 11 节）
不必删节次，改时间即可。

## 三、解析口径（实测覆盖）

> **重要**：下面这套口径是在**真实页面**（珠海科技学院正方系统）上撞出来的。
> 参照实现（Electron 版）面向的是「精简单元格」写法，直接移植会在真实页面上**全部解析失败**。
> 三个真实差异见本节末尾「富单元格页面的三个坑」。

### 周次

支持 `1-16周` / `1-8,10-16周` / `1-15周(单)` / `2-14周（双）`（全角括号）/ `5周`。

- 单双周是**整串属性**（不会出现「单双混排」），所以先判定再按分隔符切分
- 分隔符兼容 `,` `，` `;` `；` `、`
- 无法识别的文本返回**空数组**，由上层记一条警告，而不是猜一个默认值

**必须整串消费完**：先剥掉括号组（含「节」的丢弃、含「单/双」的取出、其余展开回正文），
去「周」字后剩下的必须正好是 `数字` 或 `数字-数字`，任何一段对不上就整体判为「不是周次」。
早期版本用「在整行里找 `(\d+)-(\d+)`」的宽松匹配，在真实页面上把学号
（`(2026-2027-1)-B32211`）和学时（`理论:42,实践:3` 的 `3`）都认成了周次。

### 节次

支持 `1-2节` / `第1-2节` / `1-2` / **`0102`（四位补零：前两位起、后两位止）** / `第3节`。

- 起始节 < 1 或 起 > 止 一律判为非法
- 四位补零是正方部分版本的实际写法，漏了会把课排在第 1 节
- **`ParsePeriodLabel` 要求「整串就是节次」**，不做宽松搜索（否则会把课程代码 `2026-2027` 当节次）
- **节次与周次写在同一行**时（`(1-2节)1-14周`）用 `ExtractPeriodFromMixed`：
  优先取括号内内容，其次 `数字-数字节`，最后 `第N节`

### 星期

优先用数字（`xqj` 可能是数字**也可能是字符串**「3」），数字越界或缺失时回退中文名
（`星期三` / `周三`）。表头行以「**同一行出现 ≥2 个星期列**」判定。

### HTML 抽取

- 实体解转义：命名实体 + 数字实体（十进制 / 十六进制）
- `stripTags` **刻意保留换行**（`<br>` / 块级闭合 → `\n`）：课表单元格用 `<br>` 分隔
  「课程名 / 节次周次 / 地点 / 教师 / …」，丢掉换行就没法按行切块
- `script` / `style` 整段丢弃（否则页面脚本会被当成课程名）
- **`rowspan` / `colspan` 必须展开**：真实课表用 rowspan 做布局（「上午」占两行、节次合并），
  不展开会让后续行的列号整体前移，把课挂到**错误的星期**上。展开时被覆盖的列填空白占位。
- 列表视图的 `rowspan`：同一节次的后续行**继承**上一行解析到的节次

### 富单元格页面的三个坑

真实页面（珠海科技学院）的每个课程格约 12 行：

```
中国近现代史纲要★
(1-2节)1-14周          ← 节次与周次同行
珠海 明德楼阶梯B107
郑雨
(2026-2027-1)-B32211   ← 课程代码，形如「大数字-大数字」
10-06                  ← 形如「数字-数字」
自动化2507-08,通信2501-03
考试
理论:42,实践:3          ← 逗号后有裸数字
3                      ← 裸数字（学时/学分记录条数）
42
3.0
```

| 坑 | 表现 | 对策 |
|---|---|---|
| 附加行被当成周次 | `SplitCellBlocks` 在课程代码行切块 → 整格被切成两块、课程名与教师分家 | 周次严格整串匹配 + `MaxWeek` 上限 |
| 附加行被当成节次行 | 块内先匹配到裸数字 `3` 占掉「节次行」，真正的 `(1-2节)1-14周` 再没机会提取 → **全表节次都错成同一个值** | 块内节次必须带明确标记（`节`/`第`/括号）；且**周次判定排在节次之前** |
| rowspan 未展开 | 列号前移，课挂到错误星期 | 展开 rowspan/colspan，被覆盖列填空白占位 |

### 分块（一格多门课）

以「周次行」为分块依据，但加一条**完整性前置条件**：只有当当前块**已经含上课地点行**时
才允许在周次行处切分。

参照实现无条件在周次行切分（并吞掉其后一行），在富单元格上会把单门课切成两块
（同一份输入上参照实现确实也切成 2 块）。加前置条件后：单门课保持 1 块，
真有多门课时前一块必然已含地点，仍能正确切开。

## 四、合并导入（不是覆盖）

匹配键 = `课程名|星期|起始节|结束节|起始周|结束周`（课程名归一化去空白 + 转小写）

| 情形 | 处理 |
|---|---|
| 未命中 | 新增 |
| 命中且内容一致 | 跳过（幂等，重复导入不产生重复条目） |
| 命中且内容有变化 | **沿用既有 Id** 原地更新 |

**绝不删除**既有条目：教务重新导出未必包含全部课程（可能只导了一部分，或用户手动补录过），
覆盖会静默删掉这些条目。

**整批先校验再写入**：任一条目不合法就一条都不写，避免留下「导入了一半」的课表；
写入中途出错则回滚本次新建的条目（更新既有条目的沿用原 Id，不动其数据）。

## 五、与 Electron 版的关键差异（移植时必须改的地方）

| | Electron（原实现） | Avalonia（本实现） |
|---|---|---|
| 承载容器 | 内嵌 `BrowserWindow` | **独立弹窗 `NativeWebDialog`**（见下方说明） |
| 悬浮球回传点击 | `executeJavaScript` **会 await Promise**，脚本可直接 `return new Promise(...)` | `InvokeScript` **不 await Promise**（等待中的 Promise 被序列化成 `{}`，本项目已实测）→ 脚本**同步返回**点击标志，C# 侧**轮询** |
| 注入时机 | `did-finish-load` | `NavigationCompleted` 之后（**页面就绪闸门**，见下方说明） |
| 二级页跳转 | `hardenWindow(..., { openInPage: true })` | 拦截 `NewWindowRequested`，置 `Handled = true` 后自行 `Navigate` |
| CSS 位置 | 无需处理 | 独立弹窗里 `position:fixed` **正确**贴视口右下角（内嵌时会错位） |

### 页面就绪闸门：`InvokeScript` 在页面加载完成前必定失败

这是移植时**最容易踩、也最难从表象看懂**的一条：任何页面加载完成之前调用 `InvokeScript`，
返回的不是挂起、也不是 null，而是一个**已 Faulted 的任务**。实测（`--jwcheck` + 本地页）：

```
System.AggregateException: One or more errors occurred.
 (Unable to invoke script before any page was loaded. Listen for NavigationCompleted event.)
  ---> System.InvalidOperationException: Unable to invoke script before any page was loaded.
       Listen for NavigationCompleted event.
```

同一个弹窗，等 `NavigationCompleted` 之后再调用就正常返回字符串。另外，页面跳转会把脚本
执行上下文销毁，**在飞的脚本任务会以 `TaskCanceledException`（"A task was canceled."）结束**。

在调试器里这两条异常会一直往外冒，让人以为是别的地方坏了——其实是「注入得太早」。

因此本实现引入 `Services/JwCaptureService.PageReadyGate`：

| 事件 | 闸门动作 |
|---|---|
| `AdapterCreated` | 记下「适配器已建好」，并**在此之后才发首次导航**（`Show()` 之后抢跑会丢掉这次导航） |
| `NavigationStarted` | **关闸**（在飞的脚本会被作废） |
| `NavigationCompleted` | **开闸**，注入循环随即补上悬浮球 |

- 注入循环、抓取路径（`FetchAndImportAsync`）、面板上的手动抓取三处**都先问闸门**；
  未就绪时循环只等待、不下发任何脚本
- 兜底：适配器建好 2 秒后仍未收到 `NavigationCompleted` 就放行试一次——
  否则一旦「创建 → 首次导航完成」这条链断了，悬浮球永远不会出现
- 超时**不再丢弃脚本任务**：丢弃等于没人 await，异常会冒到
  `TaskScheduler.UnobservedTaskException`；现在继续 await 把异常观察掉
- 闸门自带计数器（`InvokeAttempts` / `SkippedNotReady`），让
  「未就绪时一次都不下发」这条不变量在 `--jwcheck` 里可断言

### `InvokeScript` 的返回值是 JSON 字符串（抓不到课表的真正原因）

第二条坑紧接着第一条：`InvokeScript` 会把脚本返回值**序列化成 JSON 字符串**交给 C#，
而它自己的脚本外壳就是一层 `JSON.stringify`。于是

```js
return document.documentElement.outerHTML
```

拿回来的不是 HTML，而是「满篇 `\u003C`、一个尖括号都没有」的字符串。
真机快照实测：179KB 里 `<html` 出现 **0** 次、字面 `\u003C` 出现 **5601** 次。

实测各形态的返回值（`--jwcheck` 探针）：

| 脚本 return | C# 侧拿到 |
|---|---|
| `'ok'` | `"ok"`（带引号） |
| `200` / `true` | `200` / `true`（非字符串，原样） |
| `{a:'<b>'}` | `{"a":"\u003Cb>"}`（对象的 JSON 文本） |
| `'<div class="x">中</div>'` | `"\u003Cdiv class=\"x\">中\u003C/div>"` ← **要拆** |

后果最阴的地方在于**没有任何警告**：三条解析路径都落空，因为那些标记压根没进解析器，
界面只说「未获取到课程（页面中没有课表数据）」，看起来像「用户没导航到课表页」。

修法：`JwCaptureService` 统一拆壳（`UnwrapScriptResult`）——只对「首尾是双引号且能解成
字符串」的值生效，幂等，裸数字/布尔/对象的 JSON 文本都不受影响。解析器再加一道同样的兜底
（`ZhengfangParser.UnwrapJsonString`），让**已经落盘的旧快照**也能离线复现出正确结论。

实测（真机抓下来的 23 门课页面）：修复前 **0** 条，修复后 **25** 条
（不连续周次按设计拆多条）、覆盖周一至周五、**0** 警告。

### 为什么用独立弹窗而不是内嵌 WebView

最初按 Electron 的形状做成了**内嵌** `NativeWebView`（放在应用内的一层覆盖页上），实测有两个问题：

1. 覆盖页与应用原有内容**挤在同一块区域**，视觉上重叠；
2. 原生 WebView 面被外层容器**裁切**。

改为 `NativeWebDialog` 后：弹窗浮在应用之上、不占应用版面，且原生面自成一窗不再被裁。

**另外两个连带修正**（内嵌时也有，但弹窗下才暴露出来）：

- **悬浮球的 `position:fixed` 依赖"视口就是浏览器窗口"**。内嵌模式下视口是那个被裁切的小区域，
  `right:20px; bottom:24px` 会跑到错位置；独立弹窗里视口 = 窗口，位置才正确。
  实测：`ball 112x40 right=20 bottom=24`。
- **`Resize()` 必须在 `Show()` 之前调用**。`NativeWebDialog` 内部用 `_initialSize` / `_initialPosition`
  等字段在 `Show` 时一次性应用，Show 之后再调不生效。

### 二级页必须在同一窗口内跳转

教务系统的菜单大量用 `target="_blank"` / `window.open` 打开功能页（如「个人课表查询」）。
默认行为是**另开一个窗口**（用户看到"又多了一页"）或什么都不发生。处理方式：

```csharp
dialog.NewWindowRequested += (_, e) =>
{
    e.Handled = true;              // 取消默认的另开窗口
    if (e.Request is not null) dialog.Navigate(e.Request);   // 改在本窗口导航
};
```

`--jwcheck` 里用本地页面实测过这条链路（见第九节）。

轮询循环与批改网/雨课堂登录探测**同一模式**：`Task.Delay` + `ConfigureAwait(true)`，
保证每次探测都回到 UI 线程——`NativeWebView`/`NativeWebDialog` 都是 COM/STA 控件，
续体一旦切到线程池，`InvokeScript` 永远不会返回。

轮询间隔 1 秒（悬浮球只是取页面，可接受）；点击时脚本**先自行改文案**再置标志，
所以用户感知是即时的，不必等下一轮轮询。

### 时间表编辑器（设置 → 课表）

节次时间表是周视图、待办、提醒三处时间的**唯一来源**（`Timetable.ResolveSessionTime`），
所以它是可编辑的——各校作息差别很大（上午 4 节还是 5 节、晚上到 21:00 还是 22:30）。

| 操作 | 说明 |
|---|---|
| 改时间 | 逐节编辑起止，格式 `HH:mm` |
| 新增 / 删除节次 | 删中间不留断号：每次增删后统一重排序号 |
| 停用 / 启用单节 | **起止都是 `00:00` 即停用**：不排课、不显示、不参与先后与重叠校验 |
| 恢复默认 | 回到内置的 12 节作息 |

**保存时严格校验，非法就报错**（`Timetable.ValidatePeriods`）：

| 规则 | 失败提示 |
|---|---|
| 序号必须从 1 起且连续 | 「节次序号必须从 1 起且连续」 |
| 时间格式 `HH:mm` | 「第 N 节时间格式需为 HH:mm」 |
| 开始必须早于结束 | 「第 N 节开始时间需早于结束时间」 |
| 相邻节次不得重叠 | 「第 N 节与第 M 节时间重叠」 |
| 不超过 20 节 | 「节次数量不能超过 20 节」 |

**先校验、再落盘**，失败时**一个字节都不写**，并把原因标红显示给用户——
而不是像读取路径那样静默回退默认值。两条路径分工不同：

- **保存路径**（用户刚输入的）→ 抛异常 + 界面报错：用户需要知道哪里错了才能改
- **读取路径**（`NormalizePeriods`）→ 整体回退默认：文件坏了也得让应用起得来

编辑的是一份**副本**，点保存并通过校验后才写盘；改过任一行都会标记「有未保存改动」。
保存成功后还会**重算全部条目的起止时间**——否则时间表改了、课块上还是旧时间。

### 上课提醒

设置 → 通用 →「距上课前提醒」：上课前 N 分钟发系统通知，默认 15 分钟，`0` = 不提醒。

判定逻辑是纯函数 <c>Timetable.DueReminders</c>，三条规则缺一不可：

| 规则 | 为什么 |
|---|---|
| 还没提醒过 | 否则 30 秒一轮的轮询会把同一节课提醒到刷屏 |
| 还没开始上课 | 已开始的课再提醒没有意义；否则**打开应用就会被一串过时提醒糊住** |
| 距上课不超过提前量 | 提前量 15 分钟就不该在提前 40 分钟时提醒 |

另外**只认今天**：明天的第一节课不会在今晚被提前报出来。

用轮询（30 秒）而不是给每节课排定时器，理由是：课表可能在运行期被导入或编辑、
学期基准也可能被改，一次性排好的定时器会立刻过期；轮询则天然自愈——
休眠唤醒后发现错过了某节课，就按第二条规则静默跳过。

**前提不满足时把原因显示在控件下方**：没设「学期第一周的周一」、没导入课表、
系统通知不可用——这三种情况下提醒都不会生效，不写出来用户只会觉得功能坏了。

> **踩过的坑**：课表有三个写入点（启动读盘、教务导入、自检注入），而这条提示只有其中两个会刷新，
> **启动读盘那条漏了**。界面在异步读盘**之前**就绑定了提示，拿到一份「还没有课表」，
> 之后读了盘却不通知，提示就一直挂着——用户看到的就是「程序里明明有课表，设置里却说还没有课表」。
>
> 修法不是补一行通知，而是把课表收敛成**唯一写入口** `SetScheduleFile`
> （换文件 + 刷新条目数 + 重建网格 + 刷新提醒前提）。各写各的必然继续漏。

### 两个外壳都要挂这一页（Android 实测踩到）

课表是整页覆盖视图，宿主外壳里必须显式放它：

| 外壳 | 文件 | 是否已挂 |
|---|---|---|
| 桌面三栏 | `Views/TodoShellView.axaml` | ✅ |
| 移动抽屉 | `Views/MobileShellView.axaml`（共享项目内，非 Android 头） | ✅（补上后才有） |

### 返回与关闭：三个坑

1. **`CloseTimetable()` 必须把 `SelectedNav` 从「课表」挪走**。
   只把 `TimetableOpen = false` 的话，列表会停在一个空的课表筛选上，而 `OnNavChanged()`
   看到 key 还是「timetable」就**又把课表打开**——「关闭」表现为毫无反应。
   来路要在 `OnSelectedNavChanged` 里记：等进了 `OpenTimetable()` 再取「上一个」，
   拿到的只有课表自己。
2. **Android 系统返回键走 `TopLevel.BackRequested`，不是 `Activity.OnBackPressed`**。
   实测 override `OnBackPressed` 根本不会被调用（键被 Avalonia 在上层消费）。
   由内到外逐层关闭：登录页 → 答题页 → 设置 → 详情 → 课表 → 抽屉。
3. **返回键要放在工具栏最左**。工具栏在手机上放不下、可横向滚动，排在最后会被裁到屏幕外——
   而它是离开课表页的唯一入口（这一页盖住了抽屉，进不去设置）。

## 六、安全边界

- **不代填表单、不代提交、不注入任何凭据**：用户全程在自己的学校系统里登录，
  本工具只读取他已经打开的那个页面（与「浏览器插件抓取当前页」同一性质）
- **教务网址只接受 `https://`**（页面要输账号口令，明文 http 不可接受）
- 教务配置只存**网址**，不存账号密码（该配置在 **设置 → 账号 → 教务系统**）

## 七、学期第一周：周次 → 日期的唯一基准

教务系统的课表**只给周次**（如「第 6 周周一」），具体日期必须由「学期第一周的周一」推出来。

因此设置页有「学期第一周的周一」（`AppSettings.TermStartDate`）：

- **没配置时不编造日期**，只显示「第 N 周」——假日期比没有日期更容易误导
- 配置后周视图列头显示日期（`周日 10-18`），周次提示显示日期区间
- 输入非法日期**不落盘**（写坏基准会让整张课表的日期都错）

周次换算：`(本周一 - 学期第一周周一) / 7 + 1`，**周日归上一周**，早于第 1 周按第 1 周算。

## 八、界面

- 侧边栏新增**「课表」**导航项
- 课表是**整页覆盖**（与设置页同款），不是列表筛选：7 天 + 节次列挤在 400px 的列表栏里读不清
- 网格：**行 = 节次、列 = 周一~周日**；无课单元格只留一条极淡的边（12×7 全上底色会很花）
- 顶部：周次切换（上一周 / 本周 / 下一周）+ 「显示非本周」「周末」两个开关 + 导入课表 + 返回
- **「导入课表」不再内嵌网页**：打开的是一个独立弹窗（`NativeWebDialog`）承载教务系统，
  应用内只留一块**控制面板**（说明 + 状态 + 手动触发 + 返回课表）。
  - 面板提供两条抓取路径：**弹窗右下角的悬浮球**（主路径），以及面板上的
    **「抓取当前页课表」**（备用——万一注入被页面结构挡住，用户仍有办法抓）
  - 用户直接关掉弹窗时，面板同步收起（`Closing` 事件），不留「没有窗口的空面板」

### 网格是时间轴，不是等高表格

这是课表视图唯一必须做对的结构性决定。**行 = 节次、列 = 星期，课块按绝对像素矩形摆放**
（坐标由 `Services/TimetableLayout` 一次算好），而不是「课块塞进起始节那一格」。

原因：格子等高时，「1-2 节」的课块只占一行高，第 2 节的位置留一个空洞，
第 3 节又紧贴在第 1 节下面——整张表在视觉上是断的，读不出「这门课占了多久」。
改成时间轴后：

| 量 | 值 |
|---|---|
| 行高 | 56px |
| 行距（行顶到行顶） | 60px |
| 跨 1 节块高 | 56px |
| 跨 2 节块高 | 116px（2×56 + 1 个行距） |

于是「1-2 节」的块底（116）与「3-4 节」的块顶（120）之间正好留一个行距，
而跨节次的块本身连贯——这才是课表该有的样子。

> **踩过的坑**：`Canvas.Left`/`Canvas.Top` 是附加属性，**在 `DataTemplate` 里绑定它们不生效**
> ——所有课块都落在 (0,0)，堆成一摞。排查时看截图只像「排得奇怪」，
> 量控件坐标才看清 `bounds=0,0`。现在改为在 `ItemsControl.ContainerPrepared` 里显式
> `Canvas.SetLeft/SetTop`（该事件只给 `Container` 与 `Index`，所以用 Index 回查数据项）。

### 课程配色

按**课程名的稳定哈希**取色（`Services/CourseColor`，FNV-1a → 8 色调色板）。
同一门课永远同色，不同课尽量不同色，课程改名/重导不会串色。

刻意**不用 `string.GetHashCode()`**：它在 .NET 上每次进程启动都加盐，
会导致「今天蓝色、明天绿色」。深浅两套调色板分别手挑（深色主题下不能拿淡底色压浅字）。

### 同格多门课：分栏 + 保底可读宽度

同一天、节次区间相交的课块按区间图着色贪心分栏，左右并排而非互相压住。

分栏会带来新问题：4 门课挤一天时每栏不到 30px，课程名断成单字、地点全被截掉。
因此 **天宽有下限、单栏宽度有下限**（`MinDayWidth` / `MinColumnWidth`），
不够就让整张网格横向滚动，而不是把每一栏压成读不出来的窄条。
课块太窄时**干脆不显示地点**（截成「博文…」没有信息量），完整信息看 hover 与详情面板。

### 非本周课程：默认不画，可开关

与开源课表类应用（如 WakeUp）的通行做法一致：网格只呈现**这一周真实要上的课**，
避免「明明本周不上却显示着」的误导。

打开「显示非本周」后，其它周次的课以 42% 透明度画出，并在块内标注它实际是第几周
（角标如「1-15 周(单)」）——否则用户会以为课排错了。点开详情还会多一句明确说明。

### 其余展示逻辑

- **今天高亮**：列头用主色描边 + 淡底（仅当显示的就是今天所在的周，看别的周不高亮）- **「下一节课」**：今天尚未开始的最近一节；今天没课了则报明天第一节。
  只在显示当周时才出现——看第 3 周时提示「下一节」是错的
- **点课块看详情**：课程名、时间、节次、教师地点、周次；点别处收起。
  详情面板用 `ContentControl` 承载模板——直接绑 `SelectedBlock.XXX` 时，
  没选中会让每个子控件的绑定都报 `Value is null`（`IsVisible=false` 不阻止绑定求值）；
  另外重建网格时**按稳定键恢复选中**，否则窗口一改尺寸详情就自己关了
- **背景不透明**：课表页是整页覆盖，半透明背景会把壁纸透出来，正文对比度掉得很快

### 滚动时必须一起动的东西

课表里有**三条独立内容**：节次列、星期列头、课块画布。它们的偏移必须一致，
否则课块会落在错误的星期或节次下——**这比「看不到」严重**，因为用户会照错的读。

| 内容 | 纵向 | 横向 |
|---|---|---|
| 节次列（时间表） | **跟随网格**（由代码同步 `Offset.Y`） | 不滚（固定在左侧） |
| 星期列头 | 固定（一直可见） | **跟随网格**（由代码同步 `Offset.X`） |
| 课块画布 | 滚动源 | 滚动源 |

> **实测踩过**：列头原先不跟横向滚动。网格滚到周六时，**周三的课显示在「周一」列头下面**。
> 这条是用户报「课程和周数对不上」的真正原因——不是对齐差几个像素，是整体错了一整列。

### 两个表头必须在同一行

节次刻度列与 7 天区域各自带一个表头，**它们高度不同**：「节次」是一行，
「周一 / 10-12」是两行。两个表头各自成行时，行高按各自内容算，于是：

```
PeriodScroll 顶部Y=112      ← 「节次」表头只占一行
GridScroll   顶部Y=137.6    ← 星期表头占两行
差 25.6 → 课块比节次刻度低 12.8px（截图看起来就是「课块没跟时间表对齐」）
```

**修法**：把两个表头放进**同一个 Grid 行**（行高取内容的大者），两边主体天然对齐；
课块滚动区与节次列都加 `VerticalAlignment="Top"`。

> 顺带解决了「最大化后课表上方空一大块」：网格高度是内容高度（10 节 = 596px），
> 窗口变高后容器被拉伸，而内容默认在多余空间里**垂直居中**，整块课表就被推到中间去了。

这类错位只看截图容易被字体的视觉重心骗到，所以加了 `TTCHECK_ALIGN=1`
直接把两者的实测屏幕坐标打出来并断言（现在差 **0**）。

另外两条容易被忽略的对齐细节：

- **节次刻度的内容要居中**：`Canvas` 忽略子元素的 `HorizontalAlignment`，
  所以必须让容器**占满列宽**、由内层 `StackPanel` 居中；只靠 `HorizontalAlignment`
  会一直贴在左边，看起来像「时间表和课表各排各的」。
  刻度列宽度取 **68px**——54px 时 `08:00-08:45` 会被裁成 `08:00-08:4`，
  居中要两边留余量，不能按文字裸宽算。
- **空状态提示别顶在最上面**：它用 `VerticalAlignment="Top"` 时会正好压在星期列头的日期上
  （实测截图里「12-21」与提示文字叠在一起）。现在它在网格区域内垂直居中。

## 八之二、CLI 验证开关（`--jwcheck`）

教务弹窗链路有几个环节在离屏自检里**测不到**，而任一失效功能就整体不可用，
因此单列一个开关逐项验证（不需要教务账号，只验链路）：

```powershell
# 用本地模拟课表页，完全离线（验证注入与二级页跳转）
$env:HWREMINDER_JW_LOCAL='1'
HomeworkReminder.Desktop.exe --jwcheck 20

# 用真实教务地址（验证真实站点的加载与注入）
$env:HWREMINDER_JW_URL='https://jw.example.edu.cn/'
HomeworkReminder.Desktop.exe --jwcheck 30
```

它断言并输出：弹窗创建/Show、`AdapterCreated`、页面加载完成次数、
**拦截新窗口次数**、`InvokeScript` 能否返回、**悬浮球的实测布局矩形**，
以及两组回归断言：
**页面就绪闸门**（复现「未加载完就调用」的失败、注入循环在开闸前零下发、
闸门关闭时抓取立刻返回 null、全新闸门 `IsReady == false`）与
**返回值拆壳**（脚本返回的 HTML 必须原样拿到，而不是 `\u003C` 满篇的字符串）。

「悬浮球可见」这一项读的是 `getBoundingClientRect()` 的宽高与屏幕位置——
只查 DOM 里存在是不够的（被 CSS 隐藏或尺寸为 0 时也存在），
有非零尺寸且贴合右下角才等价于「真能看见」。

## 八之三、课表页渲染自检（`--ttcheck`）

课表网格是**绝对定位的时间轴**，「1-2 节的块是否真的占两行、第 3 节是否紧接其下」
这类问题在数据层断言不出来（坐标算对了也可能被布局吃掉），必须看图。
而走 `--selfcheck` 需要登录态与真实初始化，所以单列一个开关：

```powershell
# 用当前已导入的课表渲染（没有则用内置样本）
HomeworkReminder.Desktop.exe --ttcheck out.png

# 强制用内置样本（含跨节次/单双周/同格冲突/周六有课），任何机器上都能看到全形状
$env:TTCHECK_SAMPLE='1'; HomeworkReminder.Desktop.exe --ttcheck out.png

# 额外打开「显示非本周」
HomeworkReminder.Desktop.exe --ttcheck out.png otherweeks

# 输出每个课块的矩形与渲染后的实测控件坐标（排查定位问题用）
$env:TTCHECK_VERBOSE='1'; HomeworkReminder.Desktop.exe --ttcheck out.png
```

进度与结论写在 `%TEMP%\hr-ttcheck.log`：这些模式下窗口在离屏渲染，
stdout 会被缓冲到进程退出才刷出来，中途卡住就完全看不到进度。

> **教训**：`--ttcheck` 第一次跑一直「没反应」，最后发现是用了一个**过期的 RID 构建产物**
> （`bin\Release\net10.0\win-x64`，还是一个月前的）。`dotnet build -c Release`
> 输出在 `bin\Release\net10.0`，两个目录并存。自检「没输出」时先确认跑的是哪个 exe。

### 滚动对齐自检

课表里最容易出、也最难一眼看穿的缺陷是**三块内容滚不到一起**：节次列、列头、课块是三条
独立内容，任一条不同步，课块就会落在**错误的星期或节次**下。这类问题只在滚动后才暴露，
所以自检支持把网格滚到指定位置再截图并断言：

```powershell
# 小窗口 + 横向滚 180 + 纵向滚 120，然后重新截图
$env:TTCHECK_SIZE='900x560'; $env:TTCHECK_HSCROLL='180'; $env:TTCHECK_VSCROLL='120'
HomeworkReminder.Desktop.exe --ttcheck out.png
```

日志末尾会直接给结论（三个偏移必须一致）：

```
课表自检: ... 节次行=10 课块=13 本周=13 周次=7 ...
滚动到 (180,120) 范围 836x596
  列头横向偏移=180（应=180）
  节次列纵向偏移=120（应=120）
  对齐自检：PASS —— 列头随横向滚动、节次列随纵向滚动
```

另有 `TTCHECK_NAV=N`：模拟连点 N 次「下一周 / 上一周」再点回本周，
验证周次真的会变、文案与课块跟着变（「箭头点了没反应」在数据层看不出来，得让按钮逻辑真跑一遍）。

## 十、排查解析失败的方法

各校正方页面的表格结构（合并单元格、附加行、嵌套层次）差异很大，**光凭截图无法确定**。
因此每次抓取都会把页面原文存一份到数据目录：

```
%LOCALAPPDATA%\HomeworkReminder\jw-last-capture.html
```

抓取失败时把这份文件拿来，就能离线复现并按真实结构定位问题——不要靠猜。

另外 `HWREMINDER_JW_DEBUG=1` 会打开运行日志（`jw-import.log`），
记录抓取字符数、解析条目/警告数、悬浮球点击。

## 十一、已知限制

1. **只适配正方系教务**。其它厂商（强智、URP、青果等）的课表页结构不同，
