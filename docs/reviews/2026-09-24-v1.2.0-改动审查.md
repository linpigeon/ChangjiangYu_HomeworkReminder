## 三、发现的问题与风险点

### 1. APK 的「方法名字符串核验」不可复现（结论正确，取证方式需更正）

Release APK 是 **AOT 编译**（`libaot-HomeworkReminder.dll.so`），托管成员名
（`OnRowTapped`、`MobileShellFactory`）已被剥离，按 CHANGELOG 描述的方式检索不到。
但外壳分离事实可以换一种方式证实：`libassembly-store.so` 元数据中检出了
`HomeworkReminder.Android.Views.MobileShell`——分离后的移动端外壳确实在产物内。
**建议**：把验证记录中的这句改为「assembly-store 元数据含 MobileShell」，
否则后来者按文档复现会得出「产物有问题」的错误结论。

### 2. 构建戳（0800777）与 v1.2.0 tag 指向（b4bf8d9）相差 3 个提交

产物构建于 `0800777`，tag 打在 `b4bf8d9`。中间的 `ac61e74`、`f72e630`、`b4bf8d9`
三个提交**只改 CHANGELOG**，无功能差异，实际无影响；但严格追溯时
「内嵌戳 ≠ tag 提交」会造成困惑。以后建议：先打完所有 CHANGELOG 再构建，
或在验证记录里注明「戳与 tag 之间仅文档提交」。

### 3. GitHub 端 v1.2.0 tag 对象（`42db0a4`）本地不存在

该 tag 对象是在 GitHub 服务端（release 创建时）生成的轻量 tag，本地仓库没有
这个对象；Gitea 端则是本地推送的附注 tag（`90e473e`）。两端 tag 都指向正确的
提交，无碍；下次 `git fetch --tags` 会把这个对象拉下来，属预期。

### 4. 遗留事项：GitHub issue #1 未处理

仓库存在一个 open issue（w3743，2026-09-21）：基于 `d1a1884` 报告 5 项缺陷
（跨课同名作业误合并、24h 全量校验失效、启动失败后自动同步不恢复、
已读公告过滤无开关、Cookie 清理误判成功），附本地修复分支 `fix/sync-cache-and-ui-bugs`
