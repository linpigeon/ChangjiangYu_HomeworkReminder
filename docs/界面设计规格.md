# 界面设计规格（仿 Microsoft To Do）

> 用途：把本应用的界面（结构、色板、控件、交互、响应式）**从零复刻或移植**到另一个项目。
> 本文是设计规格，技术栈为 **Avalonia 11/12 + FluentTheme**；设计语言本身可移植到任何 UI 框架。
>
> 全部数值取自真实样式文件（`App.axaml`、`Styles/TodoTheme.axaml`、`Styles/WidgetTheme.axaml`）与 16 个视图文件，
> 不是估算。参考实现：
> `HomeworkReminder/App.axaml`、`Styles/{TodoTheme,WidgetTheme}.axaml`、`Views/*.axaml`、`ViewModels/MainViewModel.cs`

---

## 0. 设计定位

**目标**：Microsoft To Do 的视觉语言——**工作区底色 + 卡片 + 单一强调色 + 细边框 + 小圆角**。

刻意的取舍（都是「像 To Do」的关键）：

| 取舍 | 说明 |
|---|---|
| 复选框做成**圆形** | Avalonia 默认是圆角方块。To Do 是圆环 → 实心圆 + 白勾 |
| 「已完成」**不画删除线** | 只用灰色圆形对勾 + 文字灰化（To Do 桌面版也不画删除线） |
| 列表行**用 `Border` 承载**，不用 `ListBox` | 选中/悬停态靠 `Classes` 切换，样式完全自控 |
| 面板色**带 alpha** | 配合窗口 AcrylicBlur；有壁纸时透出壁纸 |
| 强调色**只有一个** | 蓝色。图标、选中态、主按钮都用它，不再引入第二个彩色 |

### 1.2 壁纸与透明度（运行时计算，**不能只靠静态令牌**）

只有静态令牌不够：用户可设壁纸 + 拖动透明度滑块。需要在 ViewModel 里**按主题与滑块实时算四个画刷**：

```
基准面板色（不含 alpha）
  侧边栏  #F3F2F1 / 深色 #282828
  列表区  #FAF9F8 / 深色 #232323
  表面    #FFFFFF / 深色 #2E2E2E

白度 w = max(0.15, 1 − clamp(滑块百分比, 0, 85) / 100)      // 最低 0.15，永不彻底透明
画刷   = ARGB(round(w*255), 基准色的 R,G,B)                  // alpha 由 w 决定
遮罩   = 浅色 #FFFFFF / 深色 #000000，Opacity = w

嵌套渲染：壁纸 Image（UniformToFill）→ 遮罩 Border → 界面内容
```

- 无壁纸时：窗口 `TransparencyLevelHint="AcrylicBlur"` 让桌面磨砂透过半透明面板
- 平台不支持透明混合时：回落到 `TransparencyBackgroundFallback="#FAF9F8"`
- 静态令牌（`TodoSidebarBackground` 等）**只作兜底**（设计器预览、行卡片）

### 1.3 字体与字号

**字体族**：用系统 UI 字体（Avalonia 默认），**不要**指定 Segoe 系——
Android/iOS 上会显示成方框。

**图标字体**（必须内嵌）：

```xml
<FontFamily x:Key="TodoIconFont">
  avares://HomeworkReminder/Assets/Fonts/fa-solid-900.ttf#Font Awesome 6 Free Solid, Segoe Fluent Icons, Segoe MDL2 Assets
</FontFamily>
```

内嵌 **Font Awesome 6 Free Solid**（CC BY 4.0，需附 `FONT-LICENSE.txt`），
回落链依次是 Segoe Fluent Icons / Segoe MDL2 Assets。用图标一律写码位：

```xml
<TextBlock Classes="icon" Text="&#xF021;" />   <!-- 刷新 -->
```

**字号阶梯**（实测用量，16 个视图文件的真实分布）：

| 字号 | 用量 | 角色 | 对应类 |
|---|---|---|---|
| 34 | 4 | 空状态大图标 | `TextBlock.icon.large`（此处局部覆盖） |
| 20 | 3 | 区块大标题 | `TextBlock.sectionHeader` |
| 19 | 2 | 详情页主标题 | 局部（详情页） |
| 16 | 1 | 图标默认 | `TextBlock.icon` |
| 15 | 3 | 面板/列表标题、头像首字 | `TextBlock.paneTitle` |
| **14** | **18** | 列表行主标题 | `TextBlock.title` |
| **13** | **25** | 导航项、设置页标签、正文 | 局部 |
| **12** | **34** | 副标题、说明、元信息（**最常用**） | `meta` / `faint` / `overdue` |
| 11 | 19 | 徽标、小按钮、提示条 | `Border.badge TextBlock` |

**字重**：只有 **`SemiBold`** 一种强调（21 处），没有 Bold/Black。

**图标字号技巧**：小组件里的旋转动画要求图标**自身**有 `RotateTransform`；
旋转通过 CSS 式动画施加在 `TextBlock` 上（见 §4.7）。

### 1.4 圆角

| 值 | 用途 |
|---|---|
| **4** | 导航项、图标按钮、设置页标签（小控件） |
| **6** | 主按钮、描边按钮、列表行、下拉项、小组件行 |
| **9** | 徽标 `Border.badge`（高度约 18 → 全圆角药丸） |
| 17 | 头像（34×34 的**一半**，即正圆） |

> 圆角**不超过 6**（除徽标与头像）：To Do 是克制的方角风格。
> 用 12/16 这类大圆角会立刻失去 To Do 的感觉。

### 1.5 间距

| 值 | 用途 |
|---|---|
| 2 | 图标与文字紧邻、行内小间隙 |
| **3** | 列表行内三行文字的行距（主标题/副标题/元信息） |
| 4 | 徽标堆叠间隙、按钮组 |
| **6** | 常见横向元素间隙；图标按钮内的「图标 + 文字」 |
| **8** | 控件内边距、行内块间隙 |
| **10** | 主要横向间隙（头像与文字、勾选框与标题） |
| **12** | 导航项内边距基准、区块间隙 |
| 18 / 22 | 详情页、设置页的大区块纵向间距 |

**区块外边距约定**：

- 侧边栏顶部 `16,14,10,10`；底部 `16,8,16,14`
- 列表头 `18,0,14,6`；列表项区 `14,16,14,6`
- 详情页 / 设置页内容 `26,22`（详情）、`36,22,36,0`（设置页分栏居中）

> 设置页内容用 `36` 左右边距 + 居中，详情页用 `26`——**详情比设置更贴边**，
> 因为详情是「读」，设置是「填」。

### 1.6 描边宽度

| 值 | 用途 |
|---|---|
| 1.4 | 圆形勾选框圆环（`Ellipse#Ring`） |
| 1.7 | 带标签开关的勾选标记（18×18） |
| 1.8 | 待办行勾选标记（20×20） |
| 1 | 卡片/警告条边框 |

## 2. 窗口与外壳结构

### 2.1 桌面窗口

```xml
<Window Width="1180" Height="760" MinWidth="960" MinHeight="580"
        WindowStartupLocation="CenterScreen"
        TransparencyLevelHint="AcrylicBlur"
        TransparencyBackgroundFallback="#FAF9F8"
        Background="Transparent"
        Icon="/Assets/app.ico" />
```

渲染层次（自下而上）：

```
Grid
 ├─ Image  壁纸（Stretch=UniformToFill，IsVisible={HasWallpaper}）
 ├─ Border 遮罩（Background={VeilBrush}，Opacity={VeilOpacity}）
 └─ Panel  界面内容
```

> `Background="Transparent"` 必须显式设——否则 AcrylicBlur 不生效。

### 2.2 桌面三栏布局

```
Grid（ShellGrid）
 ├─ Column 0: 252        侧边栏 SidebarView（ClipToBounds=True）
 ├─ Column 1: 5          分栏拖动条 GridSplitter.colsplit
 └─ Column 2: *          Grid（TodoPane）
      ├─ Column 0: 400 (MinWidth 220)   待办列表 TodoListView
      ├─ Column 1: 5                    分栏拖动条
      └─ Column 2: * (MinWidth 280)     详情 TodoDetailView（Background=SurfaceBrush）
```

**⚠️ 栏宽不要做数据绑定。** `GridSplitter` 拖动时用 `SetValue` 写
`ColumnDefinition.Width`，会**把绑定顶掉**，此后 ViewModel 侧的变化
（如收起侧边栏）就到不了界面。正确做法：初始宽度与收起/展开都由**代码后置显式应用**，
拖动结束后把宽度记入设置持久化。

侧边栏收起：列宽置 `0` + `ClipToBounds=True`（否则内容溢出绘制）。

### 2.3 设置页与登录覆盖层（同格叠加，不是弹窗）

- **设置页**：与待办区**同格叠加**，用 `IsVisible` 硬切保证终态正确
- **登录覆盖层**：盖在**第 2 栏**（内容区），不遮侧边栏；内含三个登录视图用 `IsVisible` 互斥
  （雨课堂 / 学习通 / 批改网）
- 切换时的淡入由 `pagefadein` 关键帧动画负责，**只淡入不做淡出**（原因见 §4.6）

### 2.4 移动端外壳（抽屉式）

```
Grid
 ├─ TodoListView（DrawerMode=True，全屏；头部 ☰ 按钮切抽屉）
 ├─ Border 详情二级页（全屏覆盖，TodoDialogBackground，左上角「返回」）
 ├─ Border 设置页（全屏覆盖）
 ├─ Border 应用内 WebView 页（全屏覆盖）
 ├─ Border 登录覆盖层（全屏覆盖）
 ├─ Border 抽屉遮罩（#66000000，PointerPressed 收起）
 └─ Border 抽屉（Width=300，左对齐，TodoDialogBackground，BoxShadow="4 0 24 0 #40000000"）
      └─ SidebarView
```

**关键点**：

- 覆盖层**必须用不透明的 `TodoDialogBackground`**，否则下层列表透出来
- 抽屉**用不透明底**（`SidebarView` 自身画刷带 alpha，叠底后才不透）
- 抽屉**复用同一份 `SidebarView`**，桌面与移动不分叉
- 移动端不显示 GridSplitter（没有鼠标拖动概念）

**叠放顺序即层级**：详情 < 设置 < WebView < 登录 < 遮罩 < 抽屉。

> 桌面与移动**共用同一个 MainViewModel 与全部内容部件**
>（`SidebarView` / `TodoListView` / `TodoDetailView`），只在外壳组合方式上不同。

### 3.1 侧边栏结构

```
Row 0（Auto）：用户区
  头像 34×34 圆形（有图用图，无图用姓名首字）
    └ 占位：CornerRadius=17 的 Border，Background=TodoAccent，白色 SemiBold 15px 首字
  姓名（13px SemiBold，CharacterEllipsis，ToolTip 显示全名，MaxWidth=150）
  副标题（11px，TodoTextTertiary）
  右侧：刷新图标按钮 Button.tool（ToolTip「立即同步（再次点击可取消）」）
Row 1（*）：导航 ScrollViewer → ItemsControl
Row 2（Auto）：底部「退出登录」（Button.outline，11px）+ 设置图标按钮
```

**导航项**（`Border.navrow`，三列 `Auto,*,Auto`，内容边距 `10,8`）：

```xml
<Border Classes="navrow" Classes.selected="{Binding IsSelected}" Tapped="OnNavTapped" Margin="0,1">
  <Grid ColumnDefinitions="Auto,*,Auto" Margin="10,8">
    <TextBlock Classes="icon" Text="{Binding Glyph}" Foreground="{DynamicResource TodoAccent}" />
    <TextBlock Grid.Column="1" Text="{Binding Label}" Margin="12,0,0,0" FontSize="13" />
    <Border Grid.Column="2" Classes="badge" IsVisible="{Binding HasBadge}">
      <TextBlock Text="{Binding BadgeText}" />
    </Border>
  </Grid>
</Border>
```

**图标永远用强调色**（`TodoAccent`），文字用 `TodoTextPrimary`；
选中态**只改背景与字重，不改图标色**。

### 3.2 列表区结构（`RowDefinitions="Auto,Auto,*,Auto"`）

```
Row 0：头部（☰ 抽屉按钮[仅移动] + 列表标题 + 副标题）
Row 1：提示条区（警告 / 登录态失效 / 空状态引导 / 隐藏已勾选开关）
Row 2：列表 ScrollViewer（或课程列表 ScrollViewer） + 空状态 TextBlock
Row 3：忙碌条（IsVisible={IsBusy}）
```

**空状态与列表的显隐**：整块列表 `IsVisible={List.HasAnyContent}`，
空状态 `IsVisible={!List.HasAnyContent}`。

> ⚠️ 别用「当前集合有没有项」直接判空：本应用列表有**两条通道**
>（待办 / 课程），只看一条会在另一条视图里显示错误的空状态。
> 需要一个合成的 `HasAnyContent`（按当前视图选通道）。

**列表行**（`Border.row`，三列 `Auto,*,Auto`）：

| 列 | 内容 |
|---|---|
| 0 | `CheckBox.todocircle`（圆形勾选框，20×20） |
| 1 | 主标题 `TextBlock.title`（学科名）→ 副标题行 → 元信息行 |
| 2 | 徽标栈（`Spacing=4`）：进度 / 已过期 / 已完成 |

**副标题行用 Grid 的 `*` 列让标题按实际宽度截断**：

```xml
<Grid ColumnDefinitions="*,Auto">
  <TextBlock Classes="faint" Text="{Binding DisplayTitle}" />
  <TextBlock Grid.Column="1" Classes="overdue" Text="{Binding StatusText}" Margin="6,0,0,0" />
</Grid>
```

> **不要给标题显式 `Width=200`**：手机上会盖住右侧徽标。用 `*` 列 + `TextTrimming`。

**元信息行**（`Orientation=Horizontal Spacing=6`）：截止时间 `meta` · 分隔点 `faint` · 剩余时间（未逾期 `meta` / 逾期 `overdue`）。

**徽标**（`Border.badge` + 变体）：`CornerRadius=9`、`Padding=7,2`、字号 11。
变体 `.progress`（强调软底/强调字）、`.warn`（错误底/错误字）。

> 「雨课堂已判定完成」的行**不再显示「已过期」**——剩余时间只对未完成的事项有意义。

### 3.3 详情区

用 `Panel` 叠三块，**靠 `IsVisible` 互斥**：

1. 空状态（没选中任何东西时）
2. 课程详情（学习通课程维度汇总）
3. 待办详情

> ⚠️ **两个详情面板不能各绑一个独立属性**。本应用踩过：待办详情绑 `SelectedItem`、
> 课程详情绑 `SelectedCourse`，两者**并不天然互斥**——先选课程再切到待办视图选作业，
> 两块就**叠加渲染**在一起。
>
> 正确做法两条**同时**做：
> 1. 切换视图 / 选中一方时，**清掉另一方的选中态**
> 2. 显隐用一个**合成门槛属性**（「在课程视图」**且**「已选中课程」），不依赖「碰巧互斥」
>
> 另外：合成属性若是跨对象（`List.ShowCourseList && List.HasSelectedCourse`），
> **必须把子对象的属性变化转发上来**，否则嵌套属性变了不会重求值，界面滞后一拍。

### 3.4 设置页

顶部标签用 `Button.settab` + `Classes.active`（选中：强调色字 + SemiBold + 强调软底）。
内容区左右 `36` 边距 + 居中，分区块用 `TextBlock.sectionHeader`（20px）。

登录入口**内嵌在设置页的「账号」区**，不是启动弹窗：启动直接进主界面，
登录从设置页进入。移动端同样如此。

## 4. 控件与样式清单

共 **66 个 `Style` 选择器 + 2 个 `ControlTheme`**。全部定义在 `Styles/TodoTheme.axaml`
（应用级，通过 `StyleInclude` 引入）。

> **`ControlTheme` 必须放在 `Styles.Resources` 里**：直接作为 `<Styles>` 的子元素

### 4.6 页面切换动画（`pagefadein`）

作用于 `Grid / ScrollViewer / Border / UserControl` 的同名类。**只淡入，不做淡出。**

```xml
<Style Selector="Grid.pagefadein, ScrollViewer.pagefadein, Border.pagefadein, UserControl.pagefadein">
  <Style.Animations>
    <Animation Duration="0:0:0.18" FillMode="Both">
      <KeyFrame Cue="0%">   <Setter Property="Opacity" Value="0" /> </KeyFrame>
      <KeyFrame Cue="100%"> <Setter Property="Opacity" Value="1" /> </KeyFrame>
    </Animation>
  </Style.Animations>
</Style>
```

**为什么不做淡出（这是实测结论，不是审美偏好）**：

1. 设置页与待办区是**同格叠加 + `IsVisible` 硬切**。加淡出会让切换瞬间
   两个页面同时可见、互相穿透。
2. 用 `Opacity` 的 `DoubleTransition` 做淡出在**真机上不可靠**——
   淡出方向的合成动画会让属性**停留在 1，页面关不掉**。
3. 淡入**即使动画不播，终态也是不透明**，不会出错。这个方向是安全的。

## 5. WebView 宿主页（三个登录页共用形态）

登录页是**内嵌官方网页**，所以设计要点是「别自己画表单」：

| 要点 | 说明 |
|---|---|
| 宿主 | 平台原生 WebView（桌面 WebView2 / Android `NativeWebView`） |
| 尺寸同步 | **必须让 WebView 真正可见并同步 bounds** |
| 布局 | 用 `InvalidateMeasure()` + `InvalidateArrange()` 触发重新布局 |
| 进入方式 | 从设置页「账号」区进入，**不在启动时弹** |

**⚠️ 「页面看起来偏离中心/位置不对」的根因往往是宿主没可见。**
实测一次误诊：以为登录页「空白」，实际是 `WebViewHost.IsVisible` 从未被置为
`true`——原生 WebView2 **surface 从不与宿主同步尺寸**，于是页面渲染出来但**不居中**。
排查这类问题要**先看宿主可见性与实测尺寸**，不要先怀疑网页本身。

**三个登录页的显隐必须互斥**：`YktLoginOpen` / `ChaoxingLoginOpen` / `PigaiLoginOpen`，
外层 `LoginPageOpen` 控制整层。移动端退出登录时要清**对应那个** WebView 的 Cookie
（多个登录页共用 Cookie 存储，清错了等于没清）。

## 6. 响应式与状态

### 6.1 断点策略

| 平台 | 布局 |
|---|---|
| 桌面宽（≥960） | 三栏（侧边栏 252 / 列表 ≤400 / 详情吃剩余），栏间可拖 |
| 桌面窄 / 移动 | 「抽屉 + 全屏列表 + 全屏二级页」 |

**不是靠 CSS 断点**，而是**两套外壳**（`TodoShellView` / `MobileShellView`）
复用同一批内容部件。这样样式不分叉，只有组合方式不同。

> **两套外壳都必须在共享项目里**（`HomeworkReminder/Views/`）。
> `MobileShellView` 一度放在 `HomeworkReminder.Android/Views/`，
> 后果是「渲染手机尺寸」的审计（跑在桌面头，见 §6.4）**编译不到它**——
> 审计跑得通、报告漂亮，却完全没有覆盖移动端特有的层叠顺序与返回栏。
> 唯一挡路的是它直接调 Android 的 `CookieManager` 铺答题页 cookie，
> 已抽成 `IPlatformServices.PrepareExamWebSession()`（默认空实现）。

### 6.2 窄屏自适应的三条硬规则

手机竖屏只有 **320~411dp** 宽。下面三条都是从实测缺陷反推出来的，
不是风格偏好——违反任何一条都会在窄屏上出现「被裁 / 被挤出屏幕 / 压住别人」。

**① 不写死宽度；确需固定时，用「上限」而不是「定值」。**

| 写法 | 窄屏后果（实测） |
|---|---|
| `Width="296"`（课表课程详情面板） | 320dp 屏上左边缘落到 **-10dp**，整块被切掉（裁剪 4.8dp） |
| `Margin="94,0,26,0"`（课表空状态） | 94 是手算的 26+68，而刻度列实际占位 74 → 左边多伸出 6dp |
| 横向 `StackPanel`（登录失效条） | 不给子元素换行，「去登录」按钮右边缘落到 **367dp**，被裁 7.2dp |
| `ColumnDefinition Width="400"`（列表栏） | 960dp 窗口上 400+5+280 超过可用宽度，详情栏右边缘落到 **1232.8**（超出 272.8dp） |

正确写法：

```xml
<!-- 1) 需要「文字先换行、按钮留在屏幕内」时用 Grid 的 * / Auto 两列 -->
<Grid ColumnDefinitions="*,Auto" ColumnSpacing="10"> … </Grid>

<!-- 2) 需要「宽窗口按记忆宽度、窄窗口自动收窄」时用 * 列 + MaxWidth（代码后置写上限） -->
<ColumnDefinition Width="*" MinWidth="220" />

<!-- 3) 需要按兄弟元素的实测尺寸算边界时，用代码后置在 LayoutUpdated 里写，不要用绑定 -->
```

> **同一个几何量不要在 XAML 里抄第二遍。** 课表空状态的 `94` 与详情面板的 `296`
> 都是「把别处的尺寸手算一遍抄过来」，刻度列一改宽就永久失配。

> ⚠️ **不要用 `ElementName` 绑定去读兄弟元素「自己量出来的尺寸」**（本轮真机实测的教训）。
> 空状态提示的左边距一度写成
> `Margin="{Binding Bounds.Width, ElementName=PeriodScroll, Converter=…}"`：
> **桌面 `--androidcheck` 量出来完全正确（x=74，正好贴刻度列右边界），
> Android 真机上却完全没生效** —— 叠加层左边缘停在 77dp，
> 压住节次块（26..94dp）17dp，第 3、4 节时间被切成「10:00-10:4」「10:55-11:4」。
> 刻度列宽度的变化不一定能让外层这个绑定重新求值，而离屏渲染复现不出来。
> 正确做法：在宿主视图的 `LayoutUpdated` 里读两边**已布置完**的 `Bounds` 直接写
> `Margin` / `Width`（值不变就不写，避免自激），**并打印一条实测日志**——
> 手机上没有控制台，这类问题只有实测数字能定位：
> ```
> [22:39:39.172] 空状态边界: 本视图宽=360 刻度列=68 课块区=234 → margin=(74,0,128,0)
> ```
> 这条日志（数据目录下 `timetable-layout.log`）就是判定依据；
> 改完再用 `adb` 抓屏做像素复测（叠加层左边缘应从 77dp 移到 74dp）。

**② 整页覆盖的视图，空状态与浮层要显式限制在内容区域内。**

课表空状态整行铺开时会压在星期列头与节次刻度上；
`Margin` 的左边距必须让开刻度列，且这块要**限定在课块区域内**（右侧同样留边距）。

**③ 固定宽度的面板要能被压窄，而不是整体移出屏幕。**

课表课程详情面板：宽度按「课块区宽度 − 右外边距」在代码后置里算（夹在 200..296），
`MaxWidth=296` 只作宽屏版式上限——宽屏仍是原设计，窄屏自动收窄。

### 6.3 移动端视口锚点

审计与回归都以这几个宽度为准（覆盖常见手机竖屏）：

| 宽度 | 对应机型区间 |
|---|---|
| 320 | 极窄（小米/华为的「显示大小：大」等放大模式） |
| 360 | 最主流（1080p 屏 @3x） |
| 393 | Pixel 7/8 一代 |
| 411 | 主流大屏（1440p @3.5x） |

### 6.4 界面遮挡审计（`--androidcheck`）

**这是本节最重要的一条**：上面那些缺陷**数据层断言不出来，桌面 1180x760 也复现不了**，
只有「在手机宽度下渲染并量坐标」才看得见。所以有这条命令：

```powershell
# 逐屏渲染手机尺寸并量越界；报告写到 android-layout-report.md
HomeworkReminder.Desktop.exe --androidcheck .appdata\androidcheck
# 追加：webview = 连登录页/教务导入页/答题页一起审；desktop = 顺带量 960 宽的最小桌面三栏
HomeworkReminder.Desktop.exe --androidcheck .appdata\androidcheck webview desktop
# 只测指定尺寸
$env:ANDROIDCHECK_SIZES='320x568;360x780'
```

它把移动外壳（`MainView` + 工厂，与 Android 头同一条路径）放进一个**固定尺寸的框**里
逐屏渲染，并判定三类缺陷：

| 判据 | 说明 |
|---|---|
| 视口越界 | 控件落在框外（被屏幕裁掉） |
| 祖先裁剪 | 控件超出最近的 `ClipToBounds` 祖先；落在 `ScrollViewer` 里的不算（那是滚动） |
| 文字硬裁 | 不换行且**没有省略号**时，自然宽度 > 可用宽度（用户看到半句话却不知道后面还有） |

**判定本身踩过的两个坑**（改判据前务必先想清楚参照量）：

1. **窗口尺寸不能当视口尺寸**：给窗口设 `393x851`，平台按 DPI 取整成 `393.6x851.2`，
   于是每个控件都"越界 0.6dp"。必须用一个 `Width/Height` 固定的 `Border` 当框。
2. **`TextLayout.Width` 判不出横向硬裁**：它就是"按约束排完版"的结果，
   永远 ≤ 可用宽度。空状态那句「这里没有待办事项。」在 360dp 屏上被硬裁到 108dp，
   而 `TextLayout.Width` 报的正是 108。必须另算自然宽度（`FormattedText`）。

### 6.5 界面状态

| 状态 | 表现 |
|---|---|
| `NeedsLogin` | 主界面可用（登录在设置页），列表空状态给出登录指引 |
| `Syncing` | 忙碌条 `IsVisible={IsBusy}`，刷新图标带动画 |

### 6.3 空状态文案要区分原因

同一个空列表，「未登录」与「确实没有事项」必须文案不同，否则用户不知道要去登录。

**推荐做法**：按当前视图 + 是否已登录**分别给文案**。例：

```
未登录 + 「作业」视图 → 「还没有雨课堂账号。到 设置 → 账号 扫码登录后，这里会显示作业。」
已登录 + 「作业」视图 → 「这里没有待办事项。」
```

> ⚠️ **不要用常驻横幅做登录引导**。横幅一直压在最上方占地方，
> 而列表通常是有内容的、并不需要这条提示。放到**空状态**里：有内容时不出现，
> 列表空时才出现——信息密度与场景精确匹配。
>
> 但**「登录态失效」横幅要保留**：它是「有问题才出现」，
> 与「常驻引导」性质不同。

### 6.4 角标口径必须写清楚

同一排导航里，不同项的角标可以表示**不同的量**，但要在代码注释与文档里写清：

| 导航项 | 角标含义 |
|---|---|
| 我的一天 | 今天到期 + 已过期的未完成数 |
| 计划内 | 有截止时间的未完成数 |
| 作业 | 未完成作业数 |
| **课程** | **有未完成任务点的课程数**（**不是**任务点总数——那是每门课的明细） |
| 公告 | 未读公告数 |
| 已完成 | 已完成作业数 |

> **口径不同不算问题，说不清才是问题。** 「课程」角标若用任务点总数（可能 69），
> 会和旁边「作业 23」量级不一致而显得莫名其妙。

### 6.5 时间相关文案独立刷新

倒计时与逾期标红由**独立的分钟级计时器**刷新，**不依赖同步成功**。

理由：关掉自动同步或长时间离线时，时间仍必须照常走。
跨天时额外重算「我的一天」成员资格与导航角标。逐项通知刷新，
**不动集合**（避免选中态抖动）。

## 8. 已知的界面缺陷教训（都真实发生过）

1. **两个详情面板叠加** —— 各绑独立属性并不互斥。必须清选中态 + 用合成门槛属性。
   跨对象合成的属性还要**转发子对象的属性变化**。
2. **常驻登录横幅占地方** —— 改成空状态里的引导（有内容时不出现）。
3. **课程行没有选中高亮** —— 待办行有 `Classes.selected`，课程行漏了。
   凡是可点选的行都要有选中态反馈。
4. **`Items` 是「当前导航筛选后」的集合** —— 拿它判断「有没有数据」会在
   某些视图下恒为空。判空要用合成的 `HasAnyContent`。
5. **WebView 页面「不居中/像空白」** —— 根因是宿主 `IsVisible` 没置 `true`，
   原生 surface 从未同步尺寸。**先量宿主，再怀疑网页。**
6. **裁剪/编译绑定下的约束** —— 若项目开启 `AvaloniaUseCompiledBindingsByDefault`，
   每个视图**必须声明 `x:DataType`**，缺成员或事件处理器名写错会**直接编译失败**
   （这其实是好事：把绑定错误提前到编译期）。但 `Classes.xxx="{Binding Bool}"`
   这类绑定也要成员真实存在。
7. **移动外壳放在平台头里 → 审计覆盖不到** —— 它一度在 `HomeworkReminder.Android/Views/`，
   桌面头的 `--androidcheck` 编译不到它，于是「移动端专属」的那部分永远没被测过。
   修法是抽平台钩子（`PrepareExamWebSession`）而不是「审计里复制一份视图」：
   **复制一份就一定会改一处漏一处。**
8. **「按当前尺寸记录的数据」会跨屏串味** —— 审计器自身踩到：样本数据只在第一屏注入、
   课表网格宽度沿用上一屏的窗口尺寸。13 屏里实际只有 1 屏真的测了内容。
   凡是「每屏一次」的东西，都要在每屏开头重新设置，而不是在循环外设一次。
9. **同一进程内第二次建外壳时，静态工厂已经过期** —— `MainView` 在构造时读一次
   `App.MobileShellFactory`，之后再改工厂对已建好的视图无效。审计桌面外壳必须
   **直接构造 `TodoShellView`**，否则量到的是上一轮那个移动外壳（实测：报告里
   「桌面 960 宽」那一节的控件树里全是 `MobileShellView`）。
10. **固定栏宽会在窄窗口把邻栏挤出屏幕** —— 桌面列表栏原写死 `400`，
    `400 + 5 + 详情 MinWidth 280 = 685 > 可用 664`，详情栏直接画到窗口外
    （右边缘 1232.8 / 窗口 960），而外层 Grid 没有 `ClipToBounds`，肉眼很难发现。
    改成 `*` 列 + `MaxWidth`（上限 = 用户记忆的宽度）。
11. **`--` 不能出现在 XML 注释里** —— XAML 是 XML，注释中出现连续两个连字符会
    直接编译失败（`AVLN1001: An XML comment cannot contain '--'`）。写命令行开关名时
    去掉前导 `--`。
12. **`ElementName` 绑定读兄弟元素的实测尺寸：桌面能对、真机不生效** ——
    空状态提示的 `Margin` 绑 `PeriodScroll.Bounds.Width`，`--androidcheck` 量出来
    完全正确（x=74），Android 上却停在 77dp、压住节次块 17dp。**离屏渲染复现不出来。**
    改用 `LayoutUpdated` 里读实测 `Bounds` 直接写，并落一条设备日志
    （`timetable-layout.log`）作为判定依据。详见 §6.2 ① 的警告。
13. **快速部署会在设备上留下盖住新代码的旧程序集** ——
    `files/.__override__/<abi>/*.dll` 优先于 APK 内嵌程序集加载，
    而 `adb install -r` **不会删掉它**。本轮就被它骗过：装完新包后界面行为与旧代码
    完全一致，一度误判成「修复无效」。判定：`adb shell run-as <pkg> ls files`；
    清除：`adb uninstall` 后重装。要可调试又不留覆盖目录：`-p:EmbedAssembliesIntoApk=true`。
14. **改动是否真的生效，要用设备上的实测数字证明，而不是「我改了」** ——
    本轮结论链是：设备日志（`刻度列=68 课块区=234 → margin=(74,…)`）→ 像素复测
    （叠加层左边缘 296px = 74dp，节次列止于 375px）→ 肉眼确认时间文本完整
    （改前是「10:00-10:4」「10:55-11:4」）。三条缺一条都不足以判定修复成立。
